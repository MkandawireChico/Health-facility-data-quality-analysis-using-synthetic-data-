# Power Query setup

## Before opening Power BI

From the repository root, generate the warehouse outputs:

```bash
python src/build_platform.py
```

The build creates the raw, staged and analytics CSV files under data/warehouse. Generated files are intentionally excluded from Git.

## Apply the report theme

In Power BI Desktop, select View → Themes → Browse for themes and import `dashboard/powerbi_theme.json`. The theme uses a light canvas and high-contrast text. Review contrast and font sizing again after adding custom visuals.

## Create the shared parameter

In Power BI Desktop:

1. Open Transform data.
2. Select Manage Parameters → New Parameter.
3. Name: pWarehouseRoot.
4. Type: Text.
5. Current value: the full local path to the data/warehouse directory.
6. Do not include a trailing slash.

Every file-backed query uses this parameter. Example Windows path:
C:/Users/YourName/project/data/warehouse

## Model and governance

- FactReporting removes all Ground_Truth_* columns before loading.
- FactPeerAnomaly also removes all Ground_Truth_* columns and retains only statistically flagged rows.
- FactDetectorEvaluation is a separate aggregate governance table containing synthetic-label evaluation metrics. It must not filter operational facts.
- FactDistrictProfile and FactDistrictMonthlyTrend are separate aggregates. Use DimDistrict (defined in dashboard/dax/dimension_tables.dax) to filter those district facts and DimFacility.
- Target-attainment facts retain programme-indicator grain. Connect FactFacilityIndicatorAttainment to DimFacility and DimIndicator; FactDistrictIndicatorAttainment to DimDistrict and DimIndicator; FactMonthlyIndicatorAttainment to DimDate and DimIndicator; and FactProgrammeIndicatorAttainment to DimIndicator.
- Attainment is pooled reported value divided by pooled target for the same indicator. It is not population coverage or unique people served.
- Do not create direct fact-to-fact relationships.
- Use single-direction one-to-many relationships from dimensions to facts.
- Keep all synthetic-data disclaimers visible in the report.

Resource planning facts use abstract synthetic units and illustrative assumptions only; they are not approved staffing or budget measures. Link FactFacilityResourceCapacity and FactResourceAllocationScenario to DimFacility using Facility_ID; keep Scenario as a slicer and do not create fact-to-fact relationships.

The expanded PBIX is not generated by the Python build. Save and refresh the PBIX in Power BI Desktop, then complete the report build guide's visual QA checklist.

- DimCommodity is the illustrative commodity catalogue; connect it to the two commodity facts using Commodity_ID.
- FactFacilityCommodityStock contains monthly simulated stock balances, demand, receipts, unmet demand and stockout-day estimates. Connect to DimFacility, DimCommodity and DimDate.
- FactCommodityReplenishmentPlan is a latest-snapshot worklist; connect to DimFacility and DimCommodity. It is a snapshot fact, not a monthly ledger.
- Do not create direct fact-to-fact relationships. Keep budget credits and all inventory values labelled synthetic.
- Commodity names are examples, not an approved national list. Unit costs are abstract credits, not MWK.


## Cold-chain and expiry model

Load `DimColdChainCommodity`, `FactColdChainTemperature`, `FactCommodityBatchLedger` and `FactColdChainExpiryRisk` from the matching analytics CSV outputs.

- Connect DimFacility to each fact on Facility_ID.
- Connect DimDate to each fact on Month.
- Connect DimColdChainCommodity to FactCommodityBatchLedger and FactColdChainExpiryRisk on Commodity_ID.
- FactColdChainTemperature is facility-month grain and has no commodity key; do not join it directly to commodity facts.
- Keep the batch ledger at Batch_ID × Month grain. Demand and consumption summaries belong to the facility-commodity-month expiry-risk fact, not a sum across repeated batch rows.
- Use single-direction one-to-many dimension relationships. Never create direct fact-to-fact relationships.
- Temperature limits, shelf lives, supplier identifiers, batch details and risk scores are synthetic assumptions. The generic 2–8°C range is not a product-specific standard.


## Equipment maintenance and uptime model

Load `DimEquipmentType`, `FactEquipmentAssetRegister`, `FactEquipmentAssetMonthly`, `FactFacilityEquipmentMonthly`, `FactEquipmentMaintenanceWorkOrders` and `FactEquipmentLatestAssetRisk` from the matching analytics CSV outputs.

- Connect DimEquipmentType[Equipment_Type] to the equipment register, asset-month performance, maintenance work orders and latest asset-risk snapshot.
- Connect DimFacility[Facility_ID] to each equipment fact that contains Facility_ID.
- Connect DimDate[MonthStart] to the Month field in asset-month performance, facility-month summary, work orders and latest asset-risk snapshot. Keep the asset register separate from monthly facts; its Install_Date can use a role-playing date relationship if needed.
- Treat FactEquipmentAssetRegister as the unique asset dimension in this model (one row per Asset_ID). Connect it one-to-many to FactEquipmentAssetMonthly, FactEquipmentMaintenanceWorkOrders and FactEquipmentLatestAssetRisk using Asset_ID. It is named as a register extract but serves as the asset dimension.
- Do not sum asset-level downtime from the monthly asset fact and facility-month summary together; they are two grains of the same simulated performance.
- Work-order costs should be aggregated from the work-order fact or from the monthly asset fact, not both.
- All asset records, failure rates, service intervals, criticality weights and cost credits are synthetic assumptions. See `docs/equipment_maintenance_methodology.md`.


## Facility infrastructure and utilities reliability

Load `FactFacilityInfrastructureProfiles`, `FactMonthlyInfrastructureReliability`, `FactLatestInfrastructureResilience`, `FactEquipmentInfrastructureAssociation` and `FactInfrastructureUpgradeScenarios`.

- Connect FactFacilityInfrastructureProfiles, FactMonthlyInfrastructureReliability, FactLatestInfrastructureResilience and FactInfrastructureUpgradeScenarios to DimFacility using Facility_ID.
- Connect the monthly reliability and latest resilience facts to DimDate using Month.
- FactEquipmentInfrastructureAssociation is aggregated by interruption band only and has no facility/date relationship.
- Do not create fact-to-fact relationships.
- All utility configurations, interruptions, availability scores, upgrade assumptions and abstract credits are synthetic. See `docs/infrastructure_reliability_methodology.md`.
